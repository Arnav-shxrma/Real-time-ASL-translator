PHASE 3 — DEBUGGING AND LEARNING FROM ERRORS
======================================================================

USER:
I got an error saying `AttributeError: module 'mediapipe' has no attribute 'solutions'`. What should I do?

CHATGPT:
Let's diagnose it instead of changing random lines. This can happen when the installed MediaPipe version doesn't match the API expected by the code, or when Python is importing a local file named `mediapipe.py` instead of the installed package. First, check the installed version and confirm that there isn't a conflicting file or folder in the project. In this case, using a compatible MediaPipe version fixed the API issue: we installed `mediapipe==0.10.21` in the active environment and tried the script again.

USER:
It works after that. Why did changing the version help?

CHATGPT:
The code expects an API that is available in the compatible package version. A Python library can change between releases, so a script that uses one version may fail with another. Pinning the known-compatible version makes the environment more reproducible. We should record the dependency versions in the project requirements so the same setup is easier to recreate later.

USER:
I also saw a Windows error, `WinError 32`, mentioning that `cv2.pyd` couldn't be accessed because another process was using it. Is that a model problem?

CHATGPT:
Not necessarily. `cv2.pyd` is part of the OpenCV Python package. A file-lock error can occur if another Python process or VS Code terminal is still running and holding the library open. Stop duplicate script instances, close stale terminals, and restart the active terminal before trying again. We shouldn't assume the ONNX model is broken just because a native library file is locked.

USER:

We'll present speech output and broader sign-language support as future improvements rather than features that already exist.
